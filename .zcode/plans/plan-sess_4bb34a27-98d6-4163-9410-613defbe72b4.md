# 把 dashboard 从内联 HTML 改造为 React + coss 项目

## 目标
把 `src/dashboard-html.ts`（单文件 vanilla HTML/CSS/JS 字符串）改造为独立的 React + Vite + Tailwind v4 + coss 前端项目，并实现两处 UX 变更：
- **新建进程** → 用 coss **Dialog** 弹窗展示（原内联表单移入弹窗）
- **查看日志** → **内联左右分栏布局**：选中某个进程的 Logs 后，右侧出现日志列，**左侧进程列表被挤压**（非浮层/抽屉覆盖）。这是用户明确要求的「左右侧布局，左侧会被挤压」，所以日志面板是普通 flex 列，**不用** Sheet/Drawer。

## 约束（已确认）
- 后端 REST API 与 HTTP server 逻辑**完全不动**，只改 `GET /` 如何返回页面。
- 前端独立目录 `dashboard/`，有自己的 package.json，构建产物 `dashboard/dist`。
- 测试 `tests/http-api.mjs` 只断言 `GET /` 返回包含 `<!DOCTYPE html` 和 `procm-mcp` 的 HTML，新方案兼容（需保留断言语义）。

## 文件变更总览

### 新增：`dashboard/`（React 前端项目）
```

  vite.config.ts          # outDir: 'dist', base: './'（相对路径，便于子路径托管）
  index.html              # Vite 入口，标题 "procm-mcp dashboard"
```

- `components/ui/*` 通过 coss CLI 安装：`npx shadcn@latest add @coss/dialog @coss/button @coss/input @coss/textarea @coss/field @coss/badge @coss/table @coss/card @coss/toast`，再按需补齐其本地依赖文件（参考 coss skill 的 manual install 说明，确保 import 别名 `@/components/ui/...` 对应 `dashboard/src/components/ui/...`，配置 `tsconfig paths` + `vite alias`）。

### 修改：后端服务静态文件
- **`src/http-server.ts`**：`GET /` 不再返回 `dashboardHtml()`，改为读取并返回 `dashboard/dist/index.html`；新增对 `/assets/*`（Vite 默认产物目录）以及 `dashboard/dist` 下其它静态资源的 serving（带正确 Content-Type）。若 `dashboard/dist` 不存在（未构建），退化为友好提示页（提示运行 `npm run build:dashboard`）。
- **`src/dashboard-html.ts`**：保留为兜底/未构建时的占位提示（精简为一个提示构建的页面），或直接删除并内联到 http-server。倾向保留文件但改为返回「未构建前端」的提示 HTML，避免后端启动报错。
- 静态资源根目录解析：相对 `process.cwd()` 或模块位置，需兼容 `--server` 后台运行与全局 `npm link` 两种场景。倾向打包产物随 npm 包发布（`dashboard/dist` 加入 `package.json` 的 `files`）。

### 修改：构建脚本 `package.json`
- 新增 scripts：
  - `"build:dashboard": "npm --prefix dashboard run build"`（先 `npm --prefix dashboard install` 若需）
  - `"dev:dashboard": "npm --prefix dashboard run dev"`
- `npm run build`（后端 tsc）保持不变；可加 `"prebuild"` 或在 `test` 中串联 `build:dashboard`，但为降低风险，**默认 build 仅 tsc，dashboard 构建单独命令**（README 说明）。`files` 字段加入 `dashboard/dist`。

## 两处 UX 实现要点

### 1) 新建进程 → Dialog（NewProcessDialog.tsx）
- Header 区一个「新建进程」按钮触发 Dialog（受控 open/onOpenChange，便于成功后自动关闭并刷新列表）。
- 遵循 coss dialog 的「form in dialog」不变量：**DialogHeader 在 form 外**；`<Form className="contents">`（或原生 `<form className="contents">`）包住 **DialogPanel + DialogFooter**。
- 字段沿用原表单：Name / Script* / Args(空格分隔) / Cwd* / Envs(多行 KEY=VALUE)，用 `Field + FieldLabel + Input/Textarea` 组合。
- Footer：`type="submit"` 的主按钮（Start process）+ `DialogClose render={<Button variant="ghost"/>}` 的取消按钮；按钮显式声明 `type`。
- 提交 → `POST /api/processes`，成功 → toast + 关闭 dialog + 触发列表刷新；失败 → toast(错误)。
- 保留原「bypasses allow-x」安全提示，作为 DialogDescription 或 Panel 内 hint。

### 2) 查看日志 → 内联左右分栏（App + LogPanel）
- App 主体用 flex 两列：`<div className="flex">` 左列 `ProcessList`（flex-1，可收缩）+ 右列 `LogPanel`（固定/可收缩宽度，仅当 `selectedProcessId` 存在时渲染）。
- 点进程行的 Logs 按钮 → 设 `selectedProcessId`，右列出现，左列被挤压（flex 自适应），**无浮层、无 transform、无 backdrop**。
- LogPanel：顶部标题（进程名+id）、stdout/stderr 切换（Button 或 ToggleGroup）、count 数字输入、Close 按钮（清空 selectedProcessId，右列消失）；body 为等宽字体 pre 展示 `GET /api/processes/:id/logs?stream=&count=` 返回的 text。
- 日志面板内部自带滚动（coss ScrollArea 或 overflow-auto）。

## 验证
1. `cd dashboard && npm install && npm run build` → 产出 `dashboard/dist`。
2. `npm run build`（后端 tsc 通过）。
3. `npm test` → `tests/http-api.mjs` 的 `GET / serves the dashboard page` 仍通过（返回含 `<!DOCTYPE html` 与 `procm-mcp` 的构建后 HTML）。
4. 手动：`PROCM_HTTP_PORT=7331 npm run start:server` → 打开 `http://127.0.0.1:7331` → 验证：
   - 点「新建进程」弹 Dialog，提交后列表刷新；
   - 点某进程 Logs → 右侧出现日志列，左侧表格被挤窄；切换 stdout/stderr、改 count、点 Close。

## 风险与取舍
- 引入前端构建链是最大变更：依赖体积、CI/构建时间增加。前端独立 `dashboard/` 目录隔离风险，后端构建链不变。
- 静态资源路径需处理好 `base: './'` 与子路径托管，避免 Vite 默认绝对路径 `/assets/...` 在非根路径下 404（本服务根路径 `/`，影响小，但保留相对路径更稳）。
- 全局 `npm link` 场景下 `dashboard/dist` 路径解析：以 `__dirname`（编译后 build/http-server.js 相对路径回退到 ../dashboard/dist）为准，而非 `process.cwd()`。
- 不引入测试框架；前端改动靠手动 + 现有后端 HTTP 测试覆盖 `GET /`。
