## 概述
在 FavoritesView 搜索栏右侧加一个「导入」图标按钮，点击弹出对话框：输入文件夹路径 → 后端扫描该目录顶层的项目配置文件（`package.json` / `pyproject.toml` / `Cargo.toml`）并解析出命令列表返回 → 前端用复选框列表（coss `p-checkbox-group-4` 粒子）展示，用户勾选后导入收藏夹，分类名 = 文件夹完整绝对路径。

## 已确认的关键事实
- 收藏夹是**纯前端概念**（localStorage），后端没有收藏夹持久化。所以后端扫描路由做成**无状态**的——只返回候选命令，前端用现有 `useFavorites().addFavorite` 写入。
- 后端是**原生 Node http**（非 express），路由是 `http-server.ts` 里一串 `if` 分支，照着 `POST /api/processes` 加一个分支即可。
- coss 的 checkbox / checkbox-group / label 三个原语当前**未安装**，但其依赖（`@base-ui/react` 的 `checkbox`、`checkbox-group`、`merge-props`、`use-render` 子路径 + `lucide-react` + `cn`）均已存在。我已拿到 coss 官方源码，可直接落盘，无需联网 `shadcn add`（项目也无 `components.json`）。
- 对话框沿用 `NewProcessDialog.tsx` 里的 coss dialog 套法（`Dialog/DialogPopup/DialogHeader/DialogPanel/DialogFooter`，注意「form-in-dialog」不变式）。
- FavoritesView 是纯展示组件，新增/编辑对话框的状态都在 `App.tsx`。因此新增 `onImport` prop 回调到 App，由 App 控制新对话框（照搬 `FavoriteDialog` 的受控模式）。

### 2. 后端：新增扫描解析模块 `src/project-scanner.ts`
导出 `scanProjectCommands(dir: string): Promise<ScanCandidate[]>`，无状态、只读目录顶层（**不递归**）。对每个配置文件用启发式提取命令：

| 文件 | 解析逻辑 | 生成命令 |
|---|---|---|
| `package.json` | 读 `scripts` 对象 | `npm run <name>`（script 名作 name，原始命令作 desc） |
| `pyproject.toml` | 读 `[project.scripts]` + `[tool.poetry.scripts]` | `poetry run <entry>` 或直接 `<entry>`；若无 scripts，回退 `python -m <package>` 之类——保守只取显式 scripts |
| `Cargo.toml` | 不解析具体字段，加标准命令 | `cargo run` / `cargo build` / `cargo test` / `cargo check` |

- 用 `fs/promises` 的 `stat`/`readFile`；目录不存在或非目录返回 400 风格错误（抛错让路由层转 message）。
- TOML 解析**不引入新依赖**：写一个极简的、只针对 `[section]` 和 `key = "value"` / `key = value` 的行级正则解析器（pyproject 的 scripts 段就够用，Cargo 不需要解析）。若解析不出就跳过该文件，不报错。
- 每个候选返回 `{ script, args, cwd, name?, desc? }`（cwd = 输入目录，即启动时的工作目录）。`script` 是可执行名（如 `npm`、`cargo`、`poetry`），`args` 是数组。

### 3. 后端：在 `src/http-server.ts` 加路由（约第 228 行 `/api/meta` 块之后、`/api/processes` 之前）
```ts
// POST /api/favorites/scan -> scan a dir's project files for launchable commands.
if (method === "POST" && pathname === "/api/favorites/scan") {
  const body = JSON.parse((await readBody(req)) || "{}");
  const dir = String(body.path || "").trim();
  if (!dir) { json(res, 400, { error: "path is required" }); return; }
  try {
    const candidates = await scanProjectCommands(dir);
    json(res, 200, { candidates });
  } catch (e) {
    json(res, 400, { error: toErrorMessage(e) });
  }
  return;
}
```
顶部加 `import { scanProjectCommands } from "./project-scanner.js";`。继承现有 auth/错误处理。

### 4. 前端 API 层：`dashboard/src/lib/api.ts` 加函数 + 类型
```ts
export interface ScanCandidate {
  script: string; args: string[]; cwd: string; name?: string; desc?: string;
}
export function scanDirectory(path: string): Promise<ScanCandidate[]> {
  return api<{ candidates: ScanCandidate[] }>("POST", "/api/favorites/scan", { path })
    .then((r) => r.candidates);
}
```

### 5. 前端：新增 `dashboard/src/components/ImportFavoritesDialog.tsx`
受控对话框（props: `open`, `onOpenChange`, `category`（=文件夹路径）, `onImport: (favs: Favorite[]) => void`, `onToast`）。内部状态：
- `path: string`（默认空；提交后置为已扫路径）
- `scanning: boolean`、`error: string | null`、`candidates: ScanCandidate[]`
- `selected: string[]`（CheckboxGroup 的 value，候选索引转字符串）

布局（coss dialog 套法）：
- DialogHeader: 标题「Import from folder」+ 说明
- DialogPanel 内：
  - 一行：`<Input>` 文件夹路径 + 「Scan」`<Button>`（Enter 触发扫描）
  - 扫描中显示 `<Spinner>`；出错显示红色提示
  - 有结果时：用 CheckboxGroup + Label + Checkbox 渲染可勾选列表（参考 `p-checkbox-group-4` 粒子，但这里用单层平铺即可——每个候选一项，标题显示 `name ?? script`，副文本显示完整命令 `script + args`）。提供「全选/全不选」便捷（用 `allValues` + 一个 parent Checkbox）。
- DialogFooter: Cancel + 「Import (N)」按钮（N = 已选数量，0 时禁用）

导入逻辑：把选中的候选项转成 `Favorite[]`（`category = path`（已扫的完整绝对路径），`id = makeFavoriteId()`，`createdAt = Date.now()`），调 `onImport(favs)`，成功后关闭并 toast。**去重交给 `addFavorite` 的 signature 机制**（已存在则跳过），App 层 toast 汇总「导入了 X 条，跳过 Y 条已存在」。
