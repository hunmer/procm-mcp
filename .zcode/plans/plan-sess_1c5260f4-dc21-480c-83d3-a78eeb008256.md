# Plan: Add i18n to the procm-mcp dashboard and replace all hardcoded strings

## Overview
Introduce `react-i18next` into the `dashboard/` SPA (React 19 + Vite + Tailwind v4 + coss), provide **English + Chinese** translation files, add a **language switcher with localStorage persistence** (mirroring the existing theme-toggle pattern in `src/lib/useTheme.ts`), and replace every user-facing hardcoded string across the dashboard with `t()` calls. This also fixes the existing mixed-language bug (e.g. `复制命令` / `进程已经关闭` sitting inside otherwise-English menus).

The user-facing strings live in 7 components + 2 lib files; backend error messages surfaced via toasts come from the server and stay as-is (they are not our hardcoded strings).

---

## Step 1 — Install dependencies
In `dashboard/`:
```bash
npm install i18next react-i18next --save
```

## Step 2 — i18n infrastructure (new files)

**`src/locales/en.json`** and **`src/locales/zh.json`** — nested by feature area so the ~150 keys stay manageable:
- `common` (Cancel, Delete, Stop, Close, Copy, Run, Edit, Remove, …)
- `header` (status states, Processes/Favorites tabs, running badge, Clear all, theme/lang toggles, New process, server uptime title)
- `processes` (status filter options, table column headers, filter placeholder, pagination text, toasts, context-menu items, empty states, delete/stop confirm dialogs, log-rail reopen)
- `logs` (panel title, closed-notice title+desc, Command strip, quick filters, search placeholder, copy toasts, footer counts, toggle aria-labels, overflow menu items, empty states)
- `dialogs.newProcess` / `dialogs.details` / `dialogs.favorite` (titles, descriptions, field labels + placeholders + field descriptions, validation msg, submit/cancel)
- `favorites` (filter placeholder, import button, empty states, card labels, Launch, uncategorized)
- `importDialog` (title, description, folder path, Scan, Select all/Clear all, results count, No commands found, Import button)
- `status` (running/spawning/exited/error keywords + Process error/Details)
- `presets` (Counter/Mixed streams/HTTP server/Ping labels + descriptions)
- `toasts` (App-level: removed/added/updated/already-in/imported/cleared/started variants)

Plurals & interpolation use idiomatic i18next:
- Count plurals (`process`, `favorite`, `line`, `match`, `command`) → `_one`/`_other` keys called with `{ count }` (Chinese uses the single `_other` form automatically).
- Interpolated toasts, e.g. `toasts.importedSome` = `"Imported {{added}}, skipped {{skipped}} already saved"`, called with `t("toasts.importedSome", { added, skipped })`.
- Conditional strings (theme/lang toggle aria-label) resolved with a ternary picking the right key.

**`src/i18n.ts`** — i18next init. Pattern straight from the react-i18next quick-start:
- `import i18n from "i18next"; import { initReactI18next } from "react-i18next";`
- load `en.json`/`zh.json` as resources (Vite handles JSON import; `resolveJsonModule` already `true` in tsconfig).
- `fallbackLng: "en"`, `interpolation.escapeValue: false`.
- Read persisted language from `localStorage` (mirroring `useTheme`'s `STORAGE_KEY` approach) for `lng`, falling back to `navigator.language`.
- `export default i18n;` so non-component code (`favorites.ts`) can call `i18n.t(...)`.

**`src/lib/useLanguage.ts`** — hook mirroring `useTheme.ts`: holds current language, persists to `localStorage` on change, exposes `language` + `changeLanguage(lng)`. Sets `document.documentElement.lang` on change.

## Step 3 — Wire i18n in
- **`src/main.tsx`**: add `import "./i18n";` before `App` import (so the instance is ready before first render). Also call `initTheme()` already there.
- **`index.html`**: keep `lang="en"` as the no-JS default; `useLanguage` updates it at runtime.

## Step 4 — Language switcher UI (in `App.tsx` header)
Add a compact toggle button in the header action row, right next to the existing theme-toggle button. With 2 languages it cycles EN ⇄ 中文, using a `Languages` icon from lucide-react and showing the **target** language label (mirrors the theme toggle's "switch to X" semantics). Uses `useLanguage()`. Persisted across reloads.

## Notes / risks
- **"Uncategorized" coupling**: grouping key must stay a stable constant; translating it would break the `groupByCategory` sort. Mitigated by translating only at display.
- **Plurals**: using i18next count-plural feature means English gets `_one`/`_other` and Chinese its single form — correct out of the box.
- **`verbatimModuleSyntax: true`** is on — I'll use `import type` for type-only imports of i18n where needed.
- Translation strings will be complete for both locales; the existing accidental Chinese strings (`复制命令`, `进程已经关闭`, `复制日志文件位置`, `下载日志文件`) move into `zh.json` and get proper English counterparts in `en.json`.
